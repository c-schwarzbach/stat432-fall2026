b. Does the method work?

Yes, reasonably well. With all 256 pixels QDA cannot be fitted because the class covariance matrices are singular (ranks per class range from 125 to 256, mostly below 256, because many border pixels are almost constant and others are nearly collinear). With the 40 highest-variance pixels, each class has 542 to 1194 training images, which is comfortably larger than the 40 predictors required for a full-rank sample covariance matrix. The covariance matrices are therefore invertible (smallest class eigenvalue about 2.7e-07, small but positive), although estimating 820 covariance parameters per class is still statistically demanding. The test error of 15.5% is much better than chance (90%).

Caveats: the training error (8.3%) is about half the test error, which indicates overfitting from the 10 × 820 covariance parameters. The smallest eigenvalue is also close to the tolerance, so the fit is close to the edge of numerical stability. As a check, larger screened sets fail: 50, 60, 80 pixels give singular class covariances.

Screening works because it keeps pixels that vary a lot (so each covariance matrix is well conditioned) while discarding the near-constant pixels that make the covariance matrices singular. The price is that low-variance pixels may still carry class information (an unbiased-but-lossy filter), and marginal variance does not look at the class labels at all.

Test misclassification rate: 0.3423 (vs. 0.1555 with 40 pixels); training error 0.2888. The 10-pixel model is much worse: the error more than doubles.

Why: with only 10 pixels QDA is very stable (smallest class eigenvalue about 2.4e-03, the train-test gap is only about 5 points, and both errors are high), but it is biased. Ten pixels cannot carry enough information to separate ten digit shapes, so the model underfits. The 40-pixel model adds a lot of discriminating information, and with about 550 to 1,200 images per class the added variance of estimating a 40×40 covariance matrix is worth paying. This is the bias-variance trade-off: the test error falls steadily from 5 to 40 pixels (see the sweep above) until the covariance estimates become singular at 50 pixels.

c. Interpretation

Small ρ. When ρ = 0 the two classes have identical covariance matrices (the identity), so the LDA assumption is exactly true. LDA is then the better method (about 0.172 vs. 0.201): it estimates one pooled covariance matrix, while QDA estimates two, and QDA pays extra variance for flexibility it does not need. The gap shrinks as ρ grows, and the curves cross between ρ = 0.6 and 0.8.

Large ρ. The two covariance matrices differ more and more (correlation +ρ vs. −ρ between X1 and X2), and the optimal boundary is genuinely quadratic. LDA's error stays flat near 0.167: it only sees the mean shift in X1, and the information carried by the covariance difference is invisible to a linear rule with a pooled covariance. LDA is biased, but the bias does not change with ρ. QDA captures the structure, and its error falls to 0.100 at ρ = 0.9, close to the Bayes error of about 0.084.

Bias-variance. LDA has low variance (about 10 means per class plus 55 covariance parameters) and potentially high bias; QDA has low bias but higher variance (55 covariance parameters per class, estimated from only 100 observations per class). The better method depends on whether the bias saved by QDA exceeds the extra variance it costs, which depends on how different the true covariances are.

The eight noise covariates. They carry no class information, but the methods do not know that. Each noise variable adds a mean parameter and many covariance parameters that must be estimated from limited data, and these estimation errors enter the discriminant function. For QDA the effect is larger: going from 2 to 10 variables raises the number of covariance parameters per class from 3 to 55, so with 100 observations per class the quadratic terms and log-determinants are noisy and the boundary overfits. That is why QDA is still worse than its Bayes error at all ρ and is worse than LDA for small ρ. LDA is also affected (its error is about 0.168 versus the ideal 0.159 for a linear rule that ignores the noise), but less so. Noise predictors therefore matter even though they are uninformative, and more so as the method becomes more flexible.

def gen(rng, rho, ntr, nte, p=10):
    def draw(n, k):
        mean = np.array([-1. if k==1 else 1., 0.]); r = rho if k==1 else -rho
        x12 = rng.multivariate_normal(mean, [[1,r],[r,1]], size=n)
        return np.hstack([x12, rng.standard_normal((n, p-2))])
    Xa = np.vstack([draw(ntr,1), draw(ntr,2)]); ya = np.repeat([1,2], ntr)
    Xb = np.vstack([draw(nte,1), draw(nte,2)]); yb = np.repeat([1,2], nte)
    return Xa, ya, Xb, yb

# LDA/QDA analysis and one-page report

Load only when the user explicitly invokes this skill. The user supplies the dataset, the response, and the predictors. Never assume names, sizes, or results.

## Scope
All classifiers must be LDA, QDA, or a blend of their class probabilities. Allowed extras: regularized LDA/QDA, PCA embedding before the classifier, and a blend weight `w` in [0,1]: `p = w*p_LDA + (1-w)*p_QDA`. No other model families. Compare candidates by misclassification rate.

## Protocol
1. Report the random seed; set it once, up front.
2. Check the data: missing values, constant columns, class counts, and whether every class has more observations than predictors (QDA needs this). Encode categorical predictors numerically as instructed by the user.
3. Reserve a test set (stratified by class, about 25-30%) BEFORE any modelling. Do not touch it until step 7.
4. Build stratified K-fold CV folds (K=5 or 10) on the training data only. Use the SAME folds for every candidate.
5. Candidates: plain LDA and plain QDA (mandatory baselines), plus any extensions you consider useful, such as a regularization grid, PCA with several numbers of components, or a blend weight grid. Keep the grid small to limit selection bias.
6. Any preprocessing (scaling, PCA) is estimated on the training part of each fold only. Compute the CV error and its standard error across folds for every candidate. Select the best candidate; prefer the simpler model when it is within one standard error of the best.
7. Refit the selected model with its preprocessing on all training observations. Evaluate it ONCE on the reserved test set. Report test error with a binomial standard error and a confusion matrix. Never revise the model after seeing test results.

## Report: at most ONE printed page, clearly readable
Output a single self-contained page (HTML or PDF) with these parts:
- **Title and setup**: sample sizes (train/test), number of predictors, classes with counts, seed.
- **Figure** (one, legible axes and labels): CV misclassification rate for the candidate models with error bars of one standard error, selected model highlighted.
- **Table**: candidates with their settings, CV error, SE, and a rank or selection mark. A second small table for the test confusion matrix is optional.
- **Numerical model-fitting results**: for the selected model, report class priors, the fitted settings (components, regularization, blend weight), the CV error, and the final test error with SE.
- **Brief text** (under 200 words): candidate models, the CV procedure, the selected model and why, the estimated prediction error, main findings, and limitations such as small samples, unstable covariance estimates, Gaussian and equal-covariance assumptions, selection optimism, and test-set noise.

Keep fonts at least 9 pt and verify the page count when printed. If the report exceeds one page, shorten it rather than shrinking the type.

## Style
Plain statistical language, no dataset-specific assumptions, and numbers to 3 significant digits. State clearly which numbers come from CV and which from the test set.
