Question 1: Choosing an SVM kernel

Data and method

The dataset contains 462 observations and nine predictors: sbp, tobacco, ldl, adiposity, famhist, typea, obesity, alcohol, and age. The response is chd. I recoded famhist as 1 for Absent and 2 for Present. The response is binary, and the classes are somewhat imbalanced (302 class-0 and 160 class-1 observations), so stratified folds were used.

I created five stratified folds using shuffle=True and random_state=432, and reused the exact same folds for all candidates. In every fold, a standard scaler was fitted only on the training portion, then applied to that fold's held-out portion. The SVM was fitted on the scaled training data. Misclassification rate is the proportion of incorrect predictions; the reported value is the unweighted mean of the five fold-specific rates.

I compared 18 candidates: three linear settings; nine polynomial settings (degrees 2, 3, and 4, each with C=0.1, 1, and 10); and six RBF settings. For polynomial kernels, gamma was held at scale and coef0 at 0. For the RBF kernel, gamma and C were varied as shown. All models used the SVC default decision rule and no class weights.

Preferred model

I prefer the RBF kernel with C=10 and gamma=0.01, which had the lowest mean cross-validation misclassification rate, 0.2684 (26.84%). The linear models were close (about 27.1%), so the apparent improvement is modest rather than decisive. The polynomial candidates generally performed worse. Given the small difference from the linear kernel, I would treat the RBF choice as the best candidate within this grid, not proof that it is substantially superior. A larger or repeated nested cross-validation study could assess the stability of this choice.

SVM analysis of the SAheart data

Goal and data. Predict coronary heart disease status (chd) from nine predictors in 462 observations. Family history was coded Absent=1 and Present=2. The response has 302 zeros and 160 ones. SVM is appropriate for this binary classification task with mixed-scale numeric predictors; standardization is important. Check for missing values, data leakage, and any dependence among observations before fitting.

Model selection. A fixed, stratified five-fold split (shuffle, seed 432) was reused for 18 candidates: linear, polynomial degrees 2–4, and RBF kernels. C was varied across 0.1, 1, and 10 for linear and polynomial models. For polynomial kernels, gamma=scale and coef0=0 were held fixed. Six RBF combinations varied C and gamma. Scaling was fitted inside each training fold only. The selection metric was mean fold misclassification rate.

Result. RBF with C=10 and gamma=0.01 ranked first, with mean CV error 0.2684 (26.84%). Linear SVM was close: C=0.1 gave 0.2706 and C=1 gave 0.2707. Polynomial kernels were worse in this candidate grid (best degree-3 candidate: 0.2943). Therefore the RBF model is the preferred candidate, but the small gap versus linear SVM limits confidence that the gain is meaningful.

Interpretation and caveat. The best model's cross-validated accuracy is approximately 73.2%, only modestly above the majority-class baseline of 65.4%. On the full standardized data, the RBF model had 280 support vectors (60.6% of observations), indicating a flexible boundary with many observations defining the margin. Its training error (23.2%) was below its CV error (26.8%), suggesting some optimism but not a dramatic train-CV gap. Here, larger C penalizes training errors more strongly, while larger gamma makes the RBF boundary more local and flexible. Aggregated out-of-fold predictions gave 260 true negatives, 42 false positives, 82 false negatives, and 78 true positives; sensitivity for class 1 was 48.8%, so many positive cases were missed. If missing CHD cases is costly, compare models using sensitivity, specificity, ROC-AUC, and/or a cost-sensitive threshold rather than accuracy alone. These out-of-fold figures are descriptive; final performance should ideally be assessed with an independent test set or nested CV.

# SVM Analysis

Use this workflow to decide whether and how to fit an SVM, then report a defensible final model. Work from the data in hand; do not assume an outcome.

## 1. Judge suitability
- Confirm the response type (categorical for classification, numeric for SVR); note class balance and sample size.
- Check predictors: numeric or encodable, missing values handled, scale differences (SVMs need centering and scaling), outliers, collinearity.
- Weigh dimensionality against n, and computational cost (kernel SVMs scale poorly in n).
- State plainly if SVM is a poor fit (very large n, mostly categorical predictors, need for inference) and name a simpler baseline.

## 2. Choose kernels
- Always include linear as the baseline and interpretable option.
- Add radial (RBF) as the flexible default for smooth nonlinear boundaries.
- Add polynomial or sigmoid only with a stated reason (e.g., known interaction structure).
- Justify each kernel from data features: apparent separability, dimension, n, exploratory plots. Drop kernels you cannot justify.

## 3. Tuning parameters and method
- Cost C (all kernels); gamma (RBF, polynomial); degree and coef0 (polynomial); epsilon (SVR); class weights if imbalanced.
- Use log-spaced grids for C and gamma; search coarse, then refine; ensure the optimum is not on a grid edge.
- Tune on training data only, using the same resampling as in step 4; standardize inside each fold.
- Set and record a random seed.

## 4. Evaluation for model selection
- Use repeated (stratified, for classes) k-fold CV to compare kernels and tuning values; use nested CV or a held-out test set for the final estimate.
- Match the metric to the goal: accuracy, balanced accuracy, AUC, or F1 for classes; RMSE or MAE for regression.
- When scores tie, choose the simplest model within one standard error of the best.
- Use the test set once, after the model is fixed.

## 5. Required figure and table
- One compact figure: CV performance versus tuning parameters, one line or panel per kernel, with error bars or bands and the optimum marked.
- One compact table: per kernel, best tuning values, CV metric with SE, number of support vectors, and test result if available.
- Keep labels readable; no decoration.

## 6. Interpret and report
- Report the chosen kernel, tuned values, CV and test metrics with uncertainty, and the comparison with the baseline.
- Report the support vector count or fraction and what it implies about complexity and margin tightness.
- Explain C and gamma in plain terms (regularization strength, boundary flexibility); flag over- or underfitting via the train-versus-CV gap.
- Note limitations: imbalance, scaling choices, tuning instability, no inferential output.

## 7. Length and prioritization
- The write-up must fit one printed page at 11-point font, including the figure and table.
- Priority order: (a) figure and table, (b) final model and key numbers, (c) rationale for kernel and tuning choices, (d) suitability checks and limitations.
- Cut anything that does not help justify the final model; use one-sentence bullets.
